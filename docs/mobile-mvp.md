# 手机端第一版规格

## 已确定的需求

- 用户：付杰，蓝色 2 号球衣。
- 主要入口：手机相册；不要求先把视频导到电脑。
- 手机平台：iPhone，原生 SwiftUI，最低 iOS 18。
- 视频分析和剪辑在云端执行，Mac 无需保持开机。
- GitHub：`cloudfj77-cloud/Coach-B_AI-Basketball-Coach` 私有仓库；个人媒体与凭证独立存储。

## 核心页面

以下是目标规格；当前开发版的实际范围与尚未实现事项以 README 为准。

### 训练首页

展示最近训练、累计已核对出手、命中率趋势和下次训练计划。明显区分待处理、待核对和已完成的记录。没有数据时展示空状态，不填充虚构成绩。

### 新建训练

从相册选择视频，填写日期、球员号码和衣服特征。提供上传进度、取消与重试。目标支持断点续传；前后台行为按最终手机平台实现并实机验证，不承诺系统终止 App 后仍能继续上传。

### 逐球核对

按时间排列候选出手，点击可回看原片段。支持确认命中、未命中或无法判断，补充漏掉的出手、删除误识别，修正片段起止时间。识别不出球衣号码时不能把其他球员的出手归给用户。

### 报告与训练计划

显示确认的出手数、命中数、命中率、待核对数量与视频覆盖范围。建议应关联具体片段或数据，区分观察、推测和一般训练建议。单段录像的长度不代表整场训练时长；集锦中的命中率不代表完整训练命中率。

根据已有记录生成下次训练计划，包含每项练习的时间或次数、训练重点与记录方式。历史不足时标明基线尚在建立，不能声称存在长期趋势。

### 集锦与分享

默认结构：球员开场 → 本次已确认进球的正常速度片段 → 精选慢动作 → 数据与复盘尾卡。标题为“2 号球员训练记录与复盘”。

支持画面方向校正、适度缩放、保存到手机和系统分享。每次进球数量由本次数据决定，不固定为第一次训练的 6 次。原视频保留，重新剪辑不覆盖原文件。

## 数据规则

- 每次训练拥有独立 ID；每次真实出手拥有独立事件 ID。
- 重播、慢动作和导出不产生新的出手事件。
- 命中率 = 已核对命中数 / 已核对且结果明确的出手数。分母为零时显示“暂无数据”。
- 未识别、遮挡、归属不明的片段进入待核对，不自动算作未命中。
- 修改逐球结果后重新计算报告；旧集锦标记为需要更新。
- 首次训练的视频和统计需经来源核实后导入，不用演示数据冒充已完成的分析。

## 云端任务流程

上传中 → 排队中 → 分析中 → 待核对 → 可生成集锦 → 剪辑中 → 已完成。

任务拥有持久状态、失败原因和重试入口；重试不能重复生成训练记录或重复计数。原视频和生成文件采用非公开访问，手机只可访问当前用户自己的记录。云服务配置、存储额度与处理费用在启用服务前明确。

## 第一版验收

1. 手机相册中的真实训练视频可以直接上传，过程不经过 Mac。
2. 上传完成后关闭 App，重新进入能恢复任务状态和结果。
3. 可以补记、修改和删除投篮，确认后的统计正确且跨设备会话持久保存。
4. 能生成真实可播放的集锦，方向正确、音画正常，并保存或分享。
5. 报告可追溯到逐球片段，计划与现有数据一致。
6. 上传或处理失败可恢复，原片不丢失；私人视频与密钥不进入代码仓库。

## 后续迭代

先打通相册上传、核对、真实剪辑和报告闭环，再根据实际漏检与误检样本改进识别。更详细的投篮分区、动作比较和跨次训练分析在有足够数据后加入。
